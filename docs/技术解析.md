## 2. 技术栈详解

### 2.1 前端技术

| 技术 | 作用 | 通俗解释 |
|------|------|----------|
| **React 19** | UI框架 | 就像乐高积木，用组件拼装界面 |
| **Next.js 16** | 全栈框架 | 增强版React，自带路由、服务器渲染等功能 |
| **TypeScript** | 类型系统 | 给JavaScript加上"合同"，减少错误 |
| **Tailwind CSS** | 样式框架 | 原子化CSS，像搭积木一样写样式 |
| **shadcn/ui** | 组件库 | 预制的美观组件（按钮、卡片等） |

### 2.2 后端技术

| 技术 | 作用 | 通俗解释 |
|------|------|----------|
| **Supabase** | BaaS平台 | 后端即服务，不用自己搭建服务器 |
| **PostgreSQL** | 数据库 | 存储所有数据（用户、任务、时间记录） |
| **Row Level Security** | 安全策略 | 确保用户只能看到自己的数据 |

### 2.3 状态管理

| 技术 | 作用 | 使用场景 |
|------|------|----------|
| **Zustand** | 客户端状态 | 计时器状态（正在运行、已暂停等） |
| **React Query** | 服务器状态 | 数据缓存和同步（季度、任务列表） |

### 3.2 关键概念：App Router

**什么是 App Router？**
Next.js 13+ 的新路由系统，基于文件夹结构自动生成路由。

**示例**：
```
src/app/dashboard/quarters/page.tsx  
→ 访问路径: /dashboard/quarters

src/app/dashboard/quarters/[id]/page.tsx
→ 访问路径: /dashboard/quarters/123 (动态路由)
```

**特殊文件名**：
- `page.tsx` - 页面组件
- `layout.tsx` - 布局组件（包裹子页面）
- `loading.tsx` - 加载状态
- `error.tsx` - 错误页面

### 3.3 路由组 (Route Groups)

**`(auth)` 和 `(dashboard)` 是什么？**

括号包裹的文件夹是"路由组"，不会出现在URL中。

```
app/
├── (auth)/
│   ├── layout.tsx      # 只用于认证页面的布局
│   ├── login/page.tsx  # /login
│   └── signup/page.tsx # /signup
│
└── (dashboard)/
    ├── layout.tsx      # 只用于Dashboard的布局（有侧边栏）
    └── page.tsx        # /dashboard
```

**作用**：不同页面组可以有不同的布局。

## 4. 数据流转过程

### 4.1 用户访问页面的完整流程

```
1. 用户在浏览器输入: https://your-app.vercel.app/dashboard
   │
   ▼
2. DNS解析 → Vercel CDN（全球最近的节点）
   │
   ▼
3. Vercel执行 middleware.ts
   ├─ 检查Cookie中的认证Token
   ├─ 调用Supabase验证Token是否有效
   └─ 如果未登录 → 重定向到 /login
   │
   ▼
4. 已登录，继续执行 dashboard/page.tsx (Server Component)
   ├─ 在服务器端创建Supabase客户端
   ├─ 查询数据库：SELECT * FROM quarters WHERE user_id = '...'
   ├─ 获取任务、时间记录数据
   └─ 计算进度、统计信息
   │
   ▼
5. 生成HTML发送到浏览器
   ├─ React组件渲染成HTML
   ├─ 包含初始数据（无需额外请求）
   └─ JavaScript代码实现交互
   │
   ▼
6. 浏览器显示完整页面
   ├─ 用户可以查看数据
   ├─ 点击按钮触发客户端交互
   └─ Client Components处理动态更新
```

```
1. 用户点击"添加任务"按钮
   │
   ▼
2. 弹出对话框（Client Component）
   │
   ▼
3. 填写表单，点击"保存"
```

### 5.3 环境变量的作用

**为什么需要环境变量？**

代码中写死的问题：
```typescript
// ❌ 不好的做法
const SUPABASE_URL = "https://xxx.supabase.co"  // 写死在代码里
```

使用环境变量：
```typescript
// ✅ 好的做法
const SUPABASE_URL = process.env.NEXT_PUBLIC_SUPABASE_URL
```

**优点**：
1. **安全**：密钥不会泄露到GitHub
2. **灵活**：开发环境和生产环境用不同配置
3. **方便**：换个Supabase项目不用改代码

**Vercel如何注入环境变量？**
```
构建时：
process.env.NEXT_PUBLIC_SUPABASE_URL 
→ 替换为实际值
→ 编译到代码中

运行时：
服务器端代码可以访问所有环境变量
客户端代码只能访问 NEXT_PUBLIC_* 前缀的变量
```

## 6. 核心知识点

### 6.1 Server Components vs Client Components

**Server Components（服务器组件）**
```typescript
// dashboard/page.tsx
export default async function DashboardPage() {
  // 这段代码在服务器上运行
  const supabase = await createClient()
  const { data } = await supabase.from('tasks').select('*')
  
  return <div>任务数量: {data.length}</div>
}
```

**特点**：
- ✅ 可以直接访问数据库
- ✅ 不增加客户端JS大小
- ✅ 更好的SEO
- ❌ 不能使用useState、useEffect等Hook
- ❌ 不能绑定事件（onClick等）

**Client Components（客户端组件）**
```typescript
// components/add-task-dialog.tsx
'use client'  // 必须声明

export function AddTaskDialog() {
  const [open, setOpen] = useState(false)
  
  return (
    <Dialog open={open} onOpenChange={setOpen}>
      {/* 可以使用所有React特性 */}
    </Dialog>
  )
}
```

**特点**：
- ✅ 可以使用所有React Hook
- ✅ 可以绑定事件
- ✅ 可以使用浏览器API
- ❌ 不能直接访问数据库
- ❌ 增加客户端JS大小

**最佳实践**：
- 默认使用Server Component
- 需要交互时才使用Client Component
- 混合使用（Server Component包含Client Component）

### 6.2 Middleware（中间件）

**什么是Middleware？**
在请求到达页面之前执行的代码，类似"门卫"。

```typescript
// middleware.ts
export async function middleware(request: NextRequest) {
  // 检查用户是否登录
  const user = await getUser()
  
  // 未登录访问dashboard → 重定向到登录页
  if (!user && request.nextUrl.pathname.startsWith('/dashboard')) {
    return NextResponse.redirect(new URL('/login', request.url))
  }
  
  // 已登录访问登录页 → 重定向到dashboard
  if (user && request.nextUrl.pathname === '/login') {
    return NextResponse.redirect(new URL('/dashboard', request.url))
  }
  
  return NextResponse.next()  // 放行
}
```

**执行时机**：
```
用户请求 → Middleware → 页面组件 → 返回响应
```

**常见用途**：
- 认证和授权
- 重定向
- 请求日志
- A/B测试

### 6.3 Row Level Security (RLS)

**什么是RLS？**
数据库级别的权限控制，确保用户只能访问自己的数据。

**不使用RLS的风险**：
```typescript
// ❌ 危险：用户可以篡改查询
const { data } = await supabase
  .from('tasks')
  .select('*')
  .eq('user_id', userId)  // 用户可以改userId看别人的数据
```

**使用RLS后**：
```sql
-- 在数据库层面强制执行
CREATE POLICY "Users can view own tasks" ON tasks
  FOR SELECT USING (
    quarter_id IN (
      SELECT id FROM quarters WHERE user_id = auth.uid()
    )
  );
```

**效果**：
```typescript
// ✅ 安全：数据库自动过滤
const { data } = await supabase
  .from('tasks')
  .select('*')
// 数据库只返回当前用户的数据，无论客户端怎么改查询
```

### 6.4 JWT Token认证流程

```
1. 用户登录
   ├─ 输入邮箱和密码
   └─ 发送到Supabase
   │
   ▼
2. Supabase验证凭据
   ├─ 检查密码是否正确
   └─ 生成JWT Token
   │
   ▼
3. 返回Token到浏览器
   ├─ 存储在Cookie中
   └─ 包含用户ID、过期时间等信息
   │
   ▼
4. 后续请求自动携带Token
   ├─ 浏览器自动在请求头添加Cookie
   └─ Supabase验证Token有效性
   │
   ▼
5. Token过期后自动刷新
   └─ Middleware检测到过期 → 调用refresh接口
```

**JWT Token结构**：
```
eyJhbGciOiJIUzI1NI6IkpXVCJ9.eyJ1c2VyX2lkIjoiMTIzIn0.SflKxwRJSMeKKF2QT4fwpM
│                              │                       │
Header（算法信息）             Payload（用户数据）    Signature（签名）
```

### 6.5 React Query的作用

**问题**：频繁请求数据浪费资源
```typescript
// ❌ 没有缓存
function TaskList() {
  const [tasks, setTasks] = useState([])
  
  useEffect(() => {
    fetchTasks().then(setTasks)  // 每次组件重新渲染都请求
  }, [])
}
```

**解决**：React Query自动缓存
```typescript
// ✅ 自动缓存、去重、刷新
function TaskList() {
  const { data: tasks } = useQuery({
    queryKey: ['tasks'],
    queryFn: fetchTasks,
    staleTime: 5 * 60 * 1000,  // 5分钟内使用缓存
  })
}
```

**智能特性**：
- 自动去重（多个组件请求同一数据只发一次请求）
- 后台自动刷新（数据过期时自动更新）
- 乐观更新（先更新UI，失败再回滚）

## 7. 工作原理深度解析

### 7.1 一次完整的用户交互

**场景**：用户添加一个任务

#### 前端流程
```typescript
// 1. 用户点击"添加任务"
<Button onClick={handleAddTask}>添加任务</Button>

// 2. 打开对话框（Client Component）
const [open, setOpen] = useState(false)
setOpen(true)

// 3. 填写表单
<Input value={taskName} onChange={e => setTaskName(e.target.value)} />

// 4. 提交表单
const handleSubmit = async () => {
  // 调用Supabase客户端
  const { data, error } = await supabase
    .from('tasks')
    .insert({
      quarter_id: activeQuarter.id,
      name: taskName,
      priority: 1,
      estimated_hours: 40,
    })
    .select()
    .single()
  
  if (!error) {
    // 5. 更新本地缓存（React Query）
    queryClient.invalidateQueries(['tasks'])
    // 6. 关闭对话框
    setOpen(false)
  }
}
```

#### 后端流程（Supabase）
```sql
-- 1. 接收INSERT请求

-- 2. 验证JWT Token
SELECT auth.uid()  -- 获取当前用户ID

-- 3. 检查RLS策略
-- "用户只能在自己的季度中创建任务"
SELECT 1 FROM quarters 
WHERE id = 'quarter_id' AND user_id = auth.uid()

-- 4. 执行插入
INSERT INTO tasks (quarter_id, name, priority, estimated_hours)
VALUES ('...', '学习React', 1, 40)
RETURNING *

-- 5. 返回新创建的任务数据
```

#### 实时更新（如果开启Realtime）
```typescript
// 如果用户在多个设备登录
supabase
  .channel('tasks')
  .on('postgres_changes', 
    { event: 'INSERT', schema: 'public', table: 'tasks' },
    (payload) => {
      // 其他设备自动收到更新
      queryClient.setQueryData(['tasks'], (old) => [...old, payload.new])
    }
  )
  .subscribe()
```

### 7.3 安全最佳实践

#### 1. 永远不要信任客户端
```typescript
// ❌ 错误：在客户端检查权限
if (user.role === 'admin') {
  deleteUser(userId)  // 可以在浏览器控制台伪造
}

// ✅ 正确：在数据库层面检查（RLS）
CREATE POLICY "Only admins can delete" ON users
  FOR DELETE USING (auth.jwt() ->> 'role' = 'admin');
```

## 8. 常见问题解答

### Q1: 为什么不用传统后端（Express/Django）？

**传统方式**：
```
前端 → 后端API → 数据库
     (需要自己写接口)
```

**Supabase方式**：
```
前端 → Supabase → 数据库
     (自动生成API)
```

**优势**：
- 更快的开发速度
- 自动生成RESTful API
- 内置认证系统
- 实时订阅功能

**何时用传统后端**：
- 复杂业务逻辑
- 需要定时任务
- 需要对接第三方API

### Q2: Server Component和Client Component如何选择？

**决策树**：
```
需要交互（点击、输入）？
├─ 是 → Client Component
└─ 否
    └─ 需要使用useState/useEffect？
        ├─ 是 → Client Component
        └─ 否
            └─ 需要直接访问数据库？
                ├─ 是 → Server Component
                └─ 否 → 都可以，推荐Server Component
```

### Q3: Vercel免费版够用吗？

**免费额度**：
- 100GB 带宽/月
- 无限制的部署
- 自动HTTPS
- 全球CDN

**适合**：
- 个人项目
- 小型团队
- MVP产品

**何时升级**：
- 流量超过100GB/月
- 需要团队协作功能
- 需要更长的构建时间

### Q4: 如何调试生产环境问题？

**Vercel日志**：
```
1. 访问Vercel Dashboard
2. 选择项目 → Deployments
3. 点击具体部署 → Functions
4. 查看服务器端日志
```

**Supabase日志**：
```
1. Supabase Dashboard → Logs
2. 查看数据库查询、认证事件
```

**浏览器开发者工具**：
```
F12 → Network → 查看请求响应
     → Console → 查看JavaScript错误
```
