## 📦 第二步：推送到GitHub

### 2.1 Git工作流程

```
本地更改
   ↓
git add .              ← 暂存文件
   ↓
git commit -m "..."    ← 创建提交
   ↓
git push origin main   ← 推送到GitHub
   ↓
GitHub仓库更新
```

### 2.2 .gitignore的作用

```
本地文件夹：
├── src/                  ✅ 上传（源代码）
├── node_modules/         ❌ 不上传（太大，可重新安装）
├── .env.local            ❌ 不上传（包含密钥）
├── .next/                ❌ 不上传（构建产物，可重新生成）
└── package.json          ✅ 上传（依赖列表）

.gitignore内容：
node_modules/
.env*
.next/
```

**为什么不上传这些文件？**
- `node_modules/`: 太大（可能几百MB），根据package.json重新安装即可
- `.env.local`: 包含密钥，上传会泄露
- `.next/`: 构建产物，Vercel会重新生成

## 🌐 第四步：用户访问

### 4.1 完整的请求流程

```
1. 用户在浏览器输入: https://your-app.vercel.app
   │
   ▼
2. DNS查询
   浏览器: "your-app.vercel.app的IP地址是什么？"
   DNS服务器: "这里有10个IP，给你最近的：103.x.x.x（香港）"
   │
   ▼
3. 建立HTTPS连接
   ├─ TCP三次握手
   ├─ TLS握手（加密）
   └─ 连接建立 🔒
   │
   ▼
4. 发送HTTP请求
   GET /dashboard HTTP/2
   Host: your-app.vercel.app
   Cookie: sb-access-token=...   ← 认证Token
   │
   ▼
5. Vercel Edge处理
   │
   ├─ 检查缓存
   │  └─ 静态资源（CSS、图片）直接返回
   │
   ├─ 动态请求 → 执行Serverless Function
   │  ├─ 运行middleware.ts（检查认证）
   │  ├─ 执行page.tsx（Server Component）
   │  └─ 查询Supabase数据库
   │
   └─ 生成HTML响应
   │
   ▼
6. 返回响应
   HTTP/2 200 OK
   Content-Type: text/html
   
   <!DOCTYPE html>
   <html>
     <head>...</head>
     <body>
       <div id="__next">
         <!-- 渲染好的HTML -->
       </div>
       <script src="/_next/static/chunks/main.js"></script>
     </body>
   </html>
   │
   ▼
7. 浏览器渲染
   ├─ 解析HTML
   ├─ 加载CSS和JavaScript
   ├─ React Hydration（激活交互）
   └─ 页面完全可用 ✅
```

### 4.2 首次访问 vs 再次访问

#### 首次访问（冷启动）
```
请求 → CDN → Serverless Function启动 → 执行代码 → 返回
        ↑                ↑
    缓存MISS        需要200-500ms
    
总时间: ~1-2秒
```

#### 再次访问（命中缓存）
```
请求 → CDN → 直接返回缓存
        ↑
    缓存HIT
    
总时间: ~50-100ms
```

### 4.3 Serverless Function原理

**传统服务器 vs Serverless**

传统服务器：
```
你的服务器 (24/7运行)
├─ 一直占用内存
├─ 一直消耗电费
└─ 需要自己维护

即使没有用户访问，也在运行
```

Serverless（Vercel）：
```
没有请求时: 不运行，不收费 💰
有请求时: 
   ↓
自动启动Function
   ↓
执行代码（最多60秒）
   ↓
返回结果
   ↓
自动关闭

只为执行时间付费
```

**你的每个页面都是一个Function**：
```
/dashboard/page.tsx
   ↓
编译后 → .next/server/app/dashboard/page.js
   ↓
部署为 Serverless Function
   ↓
URL访问时自动调用
```

## 🗄️ 第五步：数据库交互

### 5.1 Supabase连接流程

```
1. 浏览器/服务器 创建Supabase客户端
   const supabase = createClient(URL, KEY)
   │
   ▼
2. 执行数据库操作
   supabase.from('tasks').select('*')
   │
   ▼
3. Supabase接收请求
   https://your-project.supabase.co/rest/v1/tasks
   Headers: 
     - apikey: your_anon_key
     - Authorization: Bearer <JWT Token>
   │
   ▼
4. 验证Token
   ├─ 解析JWT
   ├─ 验证签名
   └─ 提取user_id
   │
   ▼
5. 检查RLS策略
   SELECT * FROM tasks 
   WHERE quarter_id IN (
     SELECT id FROM quarters WHERE user_id = 'xxx'  ← 自动添加
   )
   │
   ▼
6. 执行PostgreSQL查询
   │
   ▼
7. 返回JSON结果
   {
     "data": [
       { "id": "...", "name": "学习React", ... }
     ],
     "error": null
   }
```

### 5.2 认证Cookie的生命周期

```
登录时（Supabase）:
┌─────────────────────────────────────┐
│ 1. 用户输入邮箱密码                 │
│    ↓                                │
│ 2. Supabase验证凭据                 │
│    ↓                                │
│ 3. 生成JWT Token                    │
│    - access_token (1小时有效)       │
│    - refresh_token (7天有效)        │
│    ↓                                │
│ 4. 存储在Cookie中                   │
│    sb-access-token=eyJhbG...        │
│    sb-refresh-token=v1.xx...        │
└─────────────────────────────────────┘

每次请求:
┌─────────────────────────────────────┐
│ 浏览器自动发送Cookie                │
│    ↓                                │
│ Middleware检查Token是否过期         │
│    ├─ 未过期: 继续                  │
│    └─ 已过期: 使用refresh_token刷新 │
└─────────────────────────────────────┘
```

## 🎓 关键概念总结

### 构建(Build)时 vs 运行(Runtime)时

```
构建时（在Vercel服务器上）:
├─ 编译TypeScript
├─ 打包JavaScript
├─ 优化图片
├─ 生成静态页面
└─ 创建Serverless Functions

运行时（用户访问时）:
├─ 执行Serverless Function
├─ 查询数据库
├─ 渲染动态内容
└─ 返回HTML
```

### 静态 vs 动态渲染

```
静态页面（首页、关于页面）:
构建时生成HTML → 保存在CDN → 直接返回
优点: 超快（<100ms）

动态页面（Dashboard）:
每次请求生成HTML → 可显示最新数据
优点: 实时性

混合模式（Next.js智能选择）:
├─ 公开内容: 静态生成
└─ 个人数据: 动态生成
```

### Edge vs Serverless

```
Edge（CDN节点）:
├─ 运行Middleware
├─ 处理静态资源
├─ 地理位置靠近用户
└─ 响应速度 < 50ms

Serverless Function（数据中心）:
├─ 运行Server Components
├─ 查询数据库
├─ 复杂计算
└─ 响应速度 200-500ms
```

## 💡 最佳实践

### 1. 环境变量管理

```
开发环境 (.env.local):
NEXT_PUBLIC_SUPABASE_URL=http://localhost:54321
NEXT_PUBLIC_SUPABASE_ANON_KEY=local_dev_key

生产环境 (Vercel):
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=prod_anon_key

永远不要:
❌ 把.env.local提交到Git
❌ 在代码中硬编码密钥
❌ 在客户端使用service_role_key
```

### 2. 代码组织

```
src/
├── app/                    ← 页面路由
├── components/             ← 可复用组件
│   ├── ui/                 ← 通用UI组件
│   └── features/           ← 功能组件
├── lib/                    ← 工具函数
│   ├── supabase/           ← Supabase配置
│   └── utils/              ← 通用工具
└── types/                  ← TypeScript类型

原则:
✅ 相关代码放在一起
✅ 组件职责单一
✅ 可复用优先
```
